## 1. 阻断下单：旧铺铜已经进入 Gerber / ZIP

直接检查保存状态得到 17 条间距错误、4 条孔间距错误、3 条阻焊桥接错误，另有 14 条孤岛铜警告。以下不是仅有网络名冲突，而是保存的 GND 实际填充多边形包含信号中心：

| 对象 | 坐标 mm | 保存铜皮 | 重填保存后 |
|---|---|---|---|
| D4.1 / VIN5V | (69.00, 43.55) | 位于 F.Cu GND 铜内 | 不重叠 |
| R22.2 / SIG2_N | (10.15, 35.08) | 位于 F.Cu GND 铜内 | 不重叠 |
| SIG2_P 过孔 | (8.30, 39.30) | 位于 F.Cu GND 铜内 | 不重叠 |

还有 LC_SIG2N、LC_SIG2P 走线、R23.2 和其他过孔的零间距错误。按现有铜层制造会产生短路。

证据链：

1. 不重填导出的 F/B 铜层与现有 Gerber 一致（排除日期、生成器时间和文件校验注释）。
2. 强制重填后导出的 F/B 铜层与现有 Gerber 不同。
3. ZIP 内全部 11 个文件与现有 `gerber/` 对应文件逐字节一致。因此 ZIP 同样携带旧铜皮。
4. 在临时副本执行 `--refill-zones --save-board` 后，不重填复查为 0 错误；上述中心不再位于 GND 铜内。

根因是只运行带 `--refill-zones` 的 DRC，不能保证重填结果已写回磁盘。必须**重填、保存、再导出**。建议流程：

```bash
kicad-cli pcb drc --refill-zones --save-board --schematic-parity --severity-all --format json --output drc-refilled.json s3.1.kicad_pcb
kicad-cli pcb drc --schematic-parity --severity-all --format json --output drc-saved.json s3.1.kicad_pcb
```

确认第二份报告也为 0 错误后，重新导出 Gerber、钻孔并重建 ZIP；Gerber 导出同时启用 `--check-zones` 作为额外保障。最后核对 ZIP 与本次导出的文件、更新 release 备份。不能继续使用上述哈希的旧 ZIP。

## 2. 阻断按 BOM 贴片：R24–R31 料号错误、D4 料号未定

`tools/gen_bom.py:61` 与 `BOM-jlc.csv` 把 0805 / 100Ω 的 R24–R31 指向 **C17168，实际为 0402 / 0Ω**。阻值和封装均不匹配，必须改生成源及生成结果。[LCSC C17168](https://www.lcsc.com/product-detail/C17168.html)

可核对替代项 **C17408，UNI-ROYAL 0805W8F1000T5E，0805 / 100Ω / 1% / 125mW**。[LCSC C17408](https://www.lcsc.com/zh-CN/product-detail/Chip-Resistor-Surface-Mount-UniOhm_Uniroyal-Elec-0805W8F1000T5E_C17408.html)

D4 已改 SOD-323，但 `gen_bom.py:51` 和 BOM 的采购栏仍为“待确认(B5819WS SOD-323)”。不能复用 SOD-123 的 C64885。

D4 承担 **USB 供给的整机电流 + 电池充电电流**，不是只承担桥路的约 17mA。R10=2.7kΩ 时充电电流约为数百 mA，实际取决于 TP4057 曲线、温度及输入余量；官方资料的低阻区并非统一按 1000/R 精确换算，BOM 的“约 370mA”也不是保证值。[TP4057 原厂资料](https://www.toppwr.com/uploadfile/file/20230304/640302a47b738.pdf)

候选 C169530 / 晶导 B5819WS 是 SOD-323，原厂资料给出 1A 平均电流、1A 时最大正向压降 0.6V，但降额曲线使用壳温，不能据此直接保证当前 PCB 在封闭外壳中的持续电流能力。应先确定准确型号，按 `P≈VF×(I系统+I充电)` 核算，再验证 Wi-Fi、显示、蜂鸣器与充电并发时的温升、VSYS 余量。此处结论是“选型与热预算尚未闭环”，不是断言 SOD-323 必然失效。[晶导 B5819WS 原厂数据表](https://datasheet.lcsc.com/datasheet/pdf/46ea4c013e76468094dc323052117cc7.pdf?productCode=C169530)

## 3. 烧录前必须修正：固件仍选择内部 AVDD

`firmware/components/nau7802/include/nau7802/nau7802.hpp:81` 的初始化无条件调用 `set_ldo(cfg.ldo)`；第 130 行把 `PU_CTRL.AVDDS` 置 1，默认电压仍为 2.7V。

s3.1 的 AVDD 已由外部 VDD_ADC 驱动，应使用 **AVDDS=0（AVDD pin input）**，并避免之后的 `set_ldo()` 再将其置 1。仅将默认值改成 3.3V 不能解决供电源选择问题。需要板型配置，保留旧板内部 LDO 的能力。当前固件不应直接作为 s3.1 的上电测试固件。[NAU7802 Rev2.6，第 26 页](https://www.nuvoton.com/export/resource-files/en-us--DS_NAU7802_DataSheet_EN_Rev2.6.pdf)

## 已确认正确的部分

- USB 隔离拓扑：D4 阳极 USB_VBUS、阴极 VIN5V；D3 阳极 EXP_5V、阴极 VIN5V。逻辑上阻断扩展 5V 反向向 USB 供电。文件审查不等于实板测量，肖特基反向漏电也不等于严格零电流。
- 外部模拟轨连接：U7.3、U1.1 REFP、U1.15 DVDD、U1.16 AVDD、J2.1 和 J11.1 E+ 均在 VDD_ADC；U7.1 GND、U7.2 VSYS 输入。
- 两路 LC1330 按输入电阻 410Ω 估算，3.3V 时总桥流约 16.1mA；按 400Ω 约 16.5mA，叠加 HT7533-1 输出正偏差约 17mA。加 ADC 等负载后应按约 20mA 级评估，已经不再受 NAU7802 内部 LDO 的 10mA 限制。
- HT7533-1 官方表中 100mA 是指定条件下典型能力，最小项为 70mA；桥路负载有余量。其 25/55mV 典型/最大压差条件是 **1mA**，不可直接当作 20mA 时的保证值。低电池电压下的稳定工作范围仍需实测。[Holtek HT75xx-1，第 7 页](https://www.holtek.com/webapi/116711/HT75xx-1v281.pdf)
- CPL 有 73 个唯一位号，与 BOM-jlc 的非 DNP 元件集合一致，板上位置、值与封装匹配。贴片厂最终旋转角与极性仍需在上传预览按 pin 1 核对。
- ZIP 是制造文件归档，包含双面铜、阻焊、锡膏、丝印、板框、钻孔及 job 文件；问题是铜层内容陈旧，并非 ZIP 文件类型错误。

## 次要文件问题与实测边界

- `tools/gen_bom.py:106–113` 对 BOM.csv 未进行 CSV 转义。36 行数据中 17 行因位号/描述含逗号而超出 8 列。应统一用 `csv.writer`。BOM-jlc.csv 的 36 行均为正确的 8 列。
- BOM-jlc 仍列出 D3、C23、C24 三个 DNP 位号，而 CPL 已排除。上传时必须确保这些项确实标为不贴，或生成仅包含实贴元件的装配 BOM。
- README 第 72–74、103–107、166–168 行仍有旧 VBUS、内部 2.7V/10mA、AVDD 等待初始化才出现等说明，与当前外部供电不一致。外部 VDD_ADC 建立后 AVDD 即应存在。
- 保留现有 USB 走线是一项首板风险接受；“难以找到其他 DRC 干净路线”不证明其信号质量合格。检查 USB 下载、反复枚举、持续传输，并按实际线缆测试。[Espressif ESP32-S3 PCB 指南](https://docs.espressif.com/projects/esp-hardware-design-guidelines/zh_CN/latest/esp32s3/pcb-layout-design.html)
- 3.3V 仍低于此前 LC1330 资料中的 5–12V 推荐激励，不能将改为 3.3V 写成传感器额定精度已获保证。现有厂家秤架适合验证，但仍需记录零点噪声、温漂、线性、偏载、蠕变；称重标定无法替代这些验证。
- 上电实测应覆盖：USB/电池/扩展供电及切换，D4/U6/U7 温升，充电并发，低电压边界，两路分别与同时接入，Wi-Fi/蜂鸣器干扰，目标 0.1g/0.01g 重复性。文件层面不承诺整机精度或量产可靠性。
